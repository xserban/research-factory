# Plan: hub-wide scope (IDEA-141)

Spec: `docs/specs/slice-7-hub-scope.md` (requirements HS-xx). Branch `idea-hub-scope`. Process: TDD
for `platform/` Python; JS is checked by the hub click tests (`docs/runbook-ci.md`; tests run on CI,
locally only mypy, ruff and the new test file). Tasks marked **[critical]** touch events, folds/index
or provenance and go to `rf-builder-critical`; the others go to `rf-builder`. One task per agent.
Paths are under `platform/src/factory/` (services = `services/`, ui = `hub_ui/`).

## Phase 1: scope bar and date range (no events, no write route)

**P1-01 Scope model in JS.** Files: new `ui/scope.js` (loaded by `shell.js`, which adds it to the
assets and the asset version in `services/hub_ui.py`). Pure functions: `parse(hash)`, `format(scope)`,
`inRange(published, scope)` (month granularity, year-only, undated per HS-10 to HS-12), `apply(rows,
getDate)` returning `{inScope, outOfScope, undated, n, N}`. Tests first: a JS unit test run by the
existing click-test harness (`tests/` hub tests) over fixtures: full dates, `YYYY`, `YYYY-MM`, empty
string, boundaries, `to` before `from`. Acceptance: all HS-10 to HS-12 cases pass; no DOM access.

**P1-02 Payload audit and per-work dates.** Files: `services/hub_build.py`, `hub_mining.py`,
`hub_payloads.py`, plus a short table in this plan's PR description. Tests first: a test per payload
(`shell`, `corpus`, `mining`, grids, `explore`, `findings`, `landscape`, `lenses`, `overview`) asserting
each work-bearing row has a work id and the work's `published` string (empty when undated), reusing
`ctx.publication`. Output: a list, per page, of panels that hold only pre-aggregated counts (to be
labelled "whole corpus" or given per-work rows in P1-08). Also confirms where leaderboard and results
tables live (spec open question 2). Acceptance: the tests pass; no payload grows by more than the date
string per work row (size check in the test against a fixture).

**P1-03 Scope bar component.** Files: `ui/scope.js` (render), `ui/kit.css` section, `ui/shell.js`
(mount point under the page header). Tests first: a click test: set from/to, address hash updates,
reload reproduces; keyboard operable; WCAG AA contrast on the new tokens (hub-guide five states:
empty, loading, error, partial, ready each rendered). Month inputs are `<input type=month>` with a text
fallback. Acceptance: hash `scope.from=2026-07` survives a reload and a page change (nav links carry
it); bar hidden on pages listed in HS-01.

**P1-04 "n of N" line and undated line.** Files: `ui/scope.js`, `ui/kit.css`. Tests first: click test
renders "n of N papers in scope" and "k papers have no date" and the "include undated" tick. Acceptance:
numbers come from `apply()`; the denominator is passed by the page, never inferred from the scoped rows.

**P1-05 Corpus page.** Files: `ui/pages/corpus.js`. Tests first: click test on the fixture hub: with
`scope.from` the list, the month histogram and the layer facet counts shrink and show n of N.
Acceptance: facet counts equal a recount over the visible rows; empty scope shows the empty state.

**P1-06 Miners and Data pages (per-field tables).** Files: `ui/pages/miners.js`, `ui/pages/data.js`.
Tests first: click test on a fixture miner (m-arch shaped): category counts and per-field tables are
recomputed over in-scope works; the agreement panel reads "whole pass, not scoped" while a scope is
active (HS-21). Acceptance: no agreement number changes with scope; table totals equal in-scope n.

**P1-07 Leaderboards, results and baseline rule.** Files: `ui/pages/data.js` (or the page found in
P1-02), the payload builder if the source paper id is missing per row. Tests first: a fixture with a
baseline row whose source paper is out of scope: row hidden, "k baseline rows hidden (source paper out
of scope)" shown (HS-22). Acceptance: hidden count equals a recount; rows never re-attributed.

**P1-08 Aggregated panels.** Files: per P1-02 findings (`services/hub_mining.py`, `hub_payloads.py`).
Tests first: per panel, a payload test that the per-work breakdown sums to the old aggregate (the
aggregate is unchanged). Acceptance: each panel is either recomputed in the browser or labelled "whole
corpus" (HS-20); no scoped variant payload is built.

**P1-09 Layers, explore, findings, landscape, lenses, overview.** Files: `ui/pages/explore.js`,
`findings.js`, `landscape.js`, `lenses.js`, `overview.js`. Tests first: one click test per page that a
date range changes counts and shows n of N. Acceptance: HS-03 on each page; split in two agents if a
page needs payload changes (then back through P1-08 style tests).

**P1-10 Docs and map.** Files: `docs/hub-guide.md` (one section: scope bar rules), `docs/MAP.md`
(regenerate with `scripts/gen_map.py`), `docs/backlog.md` (IDEA-141 status: phase 1 built, not
reviewed). Acceptance: guide states HS-02, HS-11, HS-21, HS-22 in two paragraphs.

Phase 1 gate: opus review of the branch (one review), mypy and ruff clean, click tests green on CI.

## Phase 2: paper sets

**P2-01 [critical] Event model and catalog.** Files: `model/paper_sets.py`, `events/catalog.py`.
Tests first: `tests/model/test_paper_sets.py`: validation of every field in spec section 3 (name
length, `PS-` id pattern, `rule` set iff `filter`, empty `works`, over 5000, duplicate ids in `works`).
Acceptance: schema registered as `paper_set.recorded` v1; `mypy --strict` clean.

**P2-02 [critical] Index fold.** Files: `index/paper_sets.py`, `index/projector` registration, schema
version bump. Tests first: fold two events and a superseding event: only the newest of a chain is live;
a rebuild from events gives identical tables (rebuildable-projection test pattern from
`tests/index`). Acceptance: tables `paper_sets`, `paper_set_works`; no write outside the projector.

**P2-03 [critical] Service `paper_sets`.** Files: `services/paper_sets.py`. Functions:
`record_set(project, actor, ...)`, `list_sets(project)`, `resolve_filter(project, rule)` (returns ids;
the only place a rule becomes ids), `get_set`. Tests first: a non-human actor refused with nothing
written; unknown work id, empty result, duplicate live name, `supersedes` not live all refused with
structured issues; a filter set stores resolved ids and does not widen after a later layer move (mirror
the layer-request test in `tests/services/test_work_layers.py`). Acceptance: HS-31, HS-32, HS-33 service
side; uses `project.index.exclusive()` and `project.record` like `move_layer`.

**P2-04 Hub write route.** Files: `services/site_server.py` (add `/api/sets/record` to the route table
and the `slot.write_lock` allow-list beside `_CHAT_ACTS`), `services/hub_write` is not used. Tests
first: `tests/services/test_site_server_*`: allowed with a human token; refused without; 4xx
structured body for each refusal of P2-03. Acceptance: route parses, calls the service, formats; no
logic in the handler.

**P2-05 `paper_sets` payload.** Files: `services/hub_build.py` (builder, `PAYLOAD_INPUTS` entry reading
only `paper_set.`), `services/hub_ui.py` (page payload lists), `services/hub_serve.py` only if the grid
queue needs the name. Tests first: payload lists live sets with n and name; a set event restales this
payload and not `corpus` (fingerprint test as in the existing per-payload fingerprint tests).
Acceptance: HS-34 data present (superseded id maps to its successor).

**P2-06 Working set and chat basket.** Files: `ui/scope.js` (working set in `sessionStorage`, mirrored
into the hash as `pick=` for sharing), `ui/shell.js` (`HUB.chatHref` accepts the working set as `only`
ids), `services/hub_chat.py` only if `parse_spec` caps below 60 ids. Tests first: click test: tick
three papers on corpus, open Chat, the basket shows exactly those three. Acceptance: one list shared
with the chat basket; the 60-id cut is stated on the page, long sets travel by `scope.set` instead.

**P2-07 Ticks in lists.** Files: `ui/pages/corpus.js`, `data.js`, `miners.js`, `explore.js` (a shared
`HUB.tick(workId)` helper in `ui/scope.js`). Tests first: click test per page; select-all of the
visible (scoped) rows. Acceptance: ticks act on visible in-scope rows only; keyboard operable.

**P2-08 Save, select and re-resolve sets.** Files: `ui/scope.js`, `ui/kit.css`, page glue. Tests first:
click test: save the current filter as a named set, reload, choose it as scope (`scope.set`), see n of
N for the intersection with the date range; superseded id shows the successor offer (HS-34).
Acceptance: HS-31 to HS-34 in the browser; refusals shown with the server's `issues` text.

**P2-09 Docs, map, status.** Files: `docs/MAP.md` (regenerate), `docs/hub-guide.md`,
`docs/build-status.md`, `docs/backlog.md` (IDEA-141 built, not reviewed). Acceptance: the new event
type, table, route and payload appear in the MAP.

Phase 2 gate: opus review focused on P2-01 to P2-04 (events, fold, route), guard mutation on the
human-actor check and on "filter set never widens"; then land via PR; no merge without the
researcher.

## Order and parallelism

P1-01 first; P1-02 in parallel with it; then P1-03, P1-04; then P1-05 to P1-09 in parallel (two or
three at a time, one worktree each); P1-10 last. Phase 2: P2-01, P2-02, P2-03 in sequence; P2-04 and
P2-05 in parallel after P2-03; P2-06 to P2-08 after P2-05; P2-09 last.

## Risks

- Payload aggregates without per-work rows (P1-02 finds them; P1-08 resolves each).
- A date source that disagrees with the work record for preprints (spec open question 1).
- Hash length: sets are carried by id, ticked picks by `pick=` capped at 60 ids.
