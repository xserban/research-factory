# Plan: discovery feed (slice 4c v1)

Date: 2026-11-11 · Status: F1–F10 built (mypy and ruff pass; tests written, not run, testing paused); branch review pending · Spec: [slice-4c-feed.md](../specs/slice-4c-feed.md) (accepted 2026-11-11) · Decision 117 (provisional) · Branch: `plan-feed`, from `plan-reference-layers` at its head when started (that branch carries the ranker, core works and the snowball dry run) · Origin: IDEA-58, the researcher's arXiv Miner

## Goal

Build v1 of the discovery feed. Per project, rank the daily arXiv listing of declared categories against the project's core works, record fetch, ranking, reactions and sends as events, and let a sent paper enter the project through the link inbox. The platform calls no model. No agent runs inside the feed cycle.

## Design

- **Ids.** `fdc_` configuration, `fdf_` fetch, `fdr_` ranking. A feed entry is keyed by arXiv id without its version (`2611.01234`). The version seen is stored on the entry.
- **Events** (spec, Events): `feed.configured` (human), `feed.fetched` (system), `feed.ranked` (system), `feed.reacted` (human), `feed.sent` (human). Each is registered in `events/catalog.py` at version 1. Payloads are `StrictModel`s in `model/feed.py`.
- **Fetched entries.** `feed.fetched` carries the raw page blob hashes and an `entries_blob`: a JSON list of the parsed entries (arXiv id, version, title, abstract, authors, categories, submitted date). The projection reads that blob. The event stays small.
- **Tables** (`index/feed.py`): `feed_configs` (latest per project), `feed_entries` (arXiv id, version, title, first fetch id, held work id or null), `feed_rankings` (id, reference hash, shown ids as JSON, the event), `feed_reactions` (entry, reaction, ranking, rank and score shown, event, actor), `feed_sends` (entry, ranking, inbox item id, event). Fold guards: `feed.configured`, `feed.reacted` and `feed.sent` fold only for a human actor. `feed.sent` folds only if its inbox item exists. `PROJECTION_VERSION` goes up by one.
- **Shared fetch cache.** `<projects_root>/.feed-cache/arxiv/<sha256 of sorted categories>/<from>_<to>/` holds the raw pages. It is a cache: a project's fetch re-archives the pages into its own blobs and records their hashes. Deleting the cache changes nothing in any project.
- **Window.** From the last complete fetch's `to`, minus `overlap_days`, to today (UTC). The first fetch looks back `interval_days`. Entries already in `feed_entries` are not ranked again.
- **Ranking.** References are the texts of `forward_core_sources` (plus the included works when `references = core+included`). The scorer is `max_cosine_scores`, and the order is `order_by_score` with ties broken by arXiv id. The shown list is the top `shown_per_cycle × (1 − exploration_share)` items, plus exploration picks drawn with `random.Random(seed)` from the rest. The seed is recorded and is derived from the ranking id, so a re-run with the same inputs differs only in id and time.
- **Nearest reference.** For each shown item, record the reference work id with the highest cosine, so the reason for the match can be shown.
- **Drift.** The finding fires on `sent_excluded / sent_screened ≥ drift_threshold` with `sent_screened ≥ drift_min_count`. It reads `feed_sends` joined with title/abstract outcomes. Severity is a warning in every mode.
