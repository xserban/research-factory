# Lane L9-brief-note: the evidence note of a brief

First read `_common.md` in this folder, then the plan `docs/plans/2026-11-20-tiers-and-autonomy.md` and the spec `docs/specs/slice-9-tiers-autonomy.md`.

Branch `tiers/L9-brief-note` (needs L1 and L2, both merged). A brief ends in a cited evidence note. Build the deterministic part: `services/brief_note.py`: `brief_note(project) -> BriefNote` computed from existing builders: the question, the PRISMA-lite counts (`report_prisma` numbers, never typed), the included works with the extracted rows (`report_evidence`), the claims with VERIFIED quotes (claims digest and the same verification as `chat_verify`; a claim without a verified quote is listed as unverified, never shown as a finding), contradictions if the finder has any, the limits (caps from `factory.tiers.plan_for`) and the label from `factory.tiers.report_label` plus the level statement (`services/level_statement.py`): 'quick review; skipped: ...; no human confirmed: ...'. Render to Markdown (`render_brief_note`) in the plain academic style of the other reports. CLI `factory brief note <project> [--format md|json]` (read-only: `CLI_READS`; add it in `cli/brief.py`). Optionally the note can be recorded as a page (find how `page_record` and the hub pages work: `services/pages*.py`; decide with a design note whether a recorded page is worth it; the default is read-only presentation, resolving L2's open question). The agent writes the prose summary through the skill (`rf-brief` step for the note): the platform computes the counts and the quote table only; add to the skill one short paragraph telling the agent to paste the computed note and add at most a short synthesis whose every sentence cites a verified quote. Tests with a small world (find how `tests/test_report_*` and `test_evidence_report*` build one), including: counts equal `report_prisma`; an unverified quote is flagged; the label and level statement are present; a project with no included works renders an honest empty note. Run your new and changed test files once each (`test_plugin.py` if the skill changes).
