## 2. Design

**Adapter `sources/pubmed.py`** (NCBI E-utilities, two phases).
- `kinds`: `KEYWORD` (the query text is PubMed syntax, sent verbatim: field tags, MeSH, booleans) and `ID_LIST` (PMIDs, for seeds and supplied links).
- Phase 1, `esearch` with `usehistory=y`: reported count, WebEnv and query key; archived before parsing.
- Phase 2, `efetch` in batches of 200 through the history (`retstart`), each batch archived, then parsed. `budget_spent` before each request; `report_progress` after each batch.
- Resume token: the `retstart` offset. WebEnv expires, so a resume re-runs `esearch`; if the count changed, the note records both counts.
- Cap: PubMed serves at most 9,999 records of one query. A larger count gives `PARTIAL` with note `esearch-cap: N reported, 9999 retrievable; split the query by date` (R-23). Date slicing is parked (section 5).
- Parsing (port): title with inline markup flattened, structured abstract with section labels, authors with ORCID and affiliation, journal venue, PubDate/MedlineDate, DOI, PMCID, MeSH descriptors then author keywords as `subjects`, publication types (retraction types flagged as the current `Work` model allows), language.
- Politeness: host `eutils.ncbi.nlm.nih.gov` at 0.34 s (0.11 s with a key); `tool=research-factory` and `email=settings.mailto` only when configured. Key from `FACTORY_NCBI_API_KEY`, else `~/.config/research-factory/ncbi-api-key`, never stored in the repository or the event log; redacted from archived URLs like the OpenAlex key.

**Probe.** `count` (`esearch rettype=count`), `matching` (`(<query>) AND (<pmid>[uid] OR …)`, chunked), `sample` returns `top` (first page by `sort=relevance`; E-utilities has no random sample). `probe_key("pubmed", work)` is the PMID.

**Registration.** `default_sources()["pubmed"]`, `INTERFACES["pubmed"] = "PubMed via NCBI E-utilities (eutils.ncbi.nlm.nih.gov)"` (the PRISMA-S interface line), `window_filter=False` in v1.

**PMC route `sources/fulltext/pmc.py`.** `Route.PMC_JATS = "pmc-jats"`, `Quality.STRUCTURED_XML`. The PMC OA web service was retired by NCBI on 2026-02-12 (checked 2026-11-14); the route reads NCBI's open bucket `pmc-oa-opendata` over HTTPS instead. PMCID from the work, else from the ID converter (`pmc.ncbi.nlm.nih.gov/tools/idconv/api/v1/articles/`, PMID or DOI). Versions are listed by prefix `PMC<id>.` and the highest is taken (slice-2 version rule); `source_version` is `PMC<id>.<ver>`. The version's JSON gives `is_pmc_openaccess`, `license_code` and `xml_url`: fetched when open access or `license_code` is `TDM` (licence recorded either way), else `not-available` / `not-open-access`. The JATS is fetched from the bucket; no `<body>` gives `no-body`. Media type `application/jats+xml`.

**Route order** (needs a decision, section 4): arXiv HTML, arXiv source, **PMC JATS**, OA PDF. The slice-2 table lists PMC fourth, after OA PDF; JATS carries sections and tables that PDF text loses, so it goes before.

**Converter.** `PandocConverter` accepts `application/jats+xml` with `-f jats` to GFM, then the existing anchoring. No new tool.

## 4. Decision to propose (124)

1) PubMed is a planned database source (`pubmed`, kinds keyword and id-list); queries are sent verbatim in PubMed syntax. 2) A query over 9,999 records is recorded partial with the cap note; it is split by the agent, not by the adapter (v1). 3) Route `pmc-jats` (quality `structured-xml`, read from NCBI's `pmc-oa-opendata` bucket; open access or TDM licence, latest version) is tried after the arXiv routes and before OA PDF, amending the order of the slice-2 table. 4) JATS is converted by pandoc (`-f jats`), extending decision 49.
