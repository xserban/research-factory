## 1. Goal and scope

**Goal:** a calm, consistent, inspiring hub for the research.
- Every screen answers one question, under a short human title, with a computed lead sentence.
- Explanations sit behind ⓘ panels, and terms carry plain definitions.
- Every figure leads to its rows and can show how it was computed ("Why this number?").

## 2. What must hold (rigour)

1. **Numbers are computed, never typed** (R-05). Every figure comes from a service payload built from events. A test pins each lead sentence and finding to its payload.
2. **Named sets.**
   - "Included" is the PRISMA final set. "Read in full" (mined) is the set of works with a live miner row.
   - Payloads carry both sets and their difference by id, with a reason per difference. The demo found 370 against 365.
   - Citation counts have one definition: the demo found `cited_in_corpus` summing to 817 against 809 resolved links. The cause is found and either fixed or shown under two names.
3. **Provenance.**
   - Every classified value shown carries its quote and anchor.
   - Every screening decision shown carries its rationale and quote.
   - "Why this number?" answers from the event log.
4. **Held-out rule (decision 37.9).** Held-out seeds' works are never hidden or masked.
5. **Deterministic analytics.** Clustering, coupling, main path, association measures, similarity and "largest gaps" are pure functions in services, each stated in its ⓘ panel. The platform calls no model.
   - Graph layout is presentation only. It runs in the browser from a fixed seed, so the same data gives the same picture.
   - Cluster membership and every count come from the service.
6. **Honest agreement.**
   - Exact-match agreement is labelled as such.
   - Where the semantic agreement measure exists (IDEA-53 line), the Miners page uses it, and both measures are named.
   - κ for screening is computed with its n.
7. **Accessibility.**
   - WCAG AA on the token pairs of all eight themes. This is a computed test; named themes that fail a pair get adjusted tokens, not an exemption.
   - Visible focus.
   - Every canvas view has a keyboard-reachable list alternative.
   - Reduced motion keeps the final state.
8. **Offline.** No external resource at run time. Fonts (Newsreader, Inter, JetBrains Mono, OFL) are vendored, subset to Latin, with their licence files.
9. **Copy** follows `COPY-GUIDE.md`, which moves into `docs/` as a binding style note for hub pages: short human titles, ⓘ panels, terms, no machine phrasing.

## 3. Architecture

- **Static pages plus JSON payloads.** Each page is a static HTML file, the same for every project, loading `kit.css`, `shell.js`, its page script and one or more payloads.
  - Payloads are built by services, cached on disk under the project's site folder, and keyed by a fingerprint of the event types they read.
  - Payloads are served with ETag and revalidation. Large payloads (graph, grid) are paged or split.
- **Services** (business logic, TDD, pure functions of a `Project`):

| Module | Builds |
|---|---|
| `services/hub_payloads.py` | `overview`, `flow`, `corpus`, `sets_reconciliation` |
| `services/hub_screening.py` | ranked curve (from decision scores and order), two-screener κ per criterion and stage, disagreements, reasons per criterion |
| `services/hub_mining.py` | miners (spec, coverage, pass A and B, agreement exact and semantic where present, by model), data grid (paged), holes, codebook labels |
| `services/hub_findings.py` | the finding cards (each a rule with its numerator, denominator and paper ids), the research cycle, openness, claims × validation |
| `services/hub_lenses.py` | matrix and expected counts, chains, trends, icicle, influence shares, association (Cramér's V with n per pair), technique adoption, similarity |
| `services/hub_graph.py` | landscape nodes and edges (corpus flag, layer, degree, cluster), foundations ranking, bibliographic coupling and clusters (deterministic label propagation or Louvain in pure Python, seeded and tie-broken by id), main path (search path count on the citation DAG, cycles broken by date then id), river arcs, reference health |
| `services/hub_living.py` | feed river (entries, ranks, reactions), horizon (`services/horizon.py`), heartbeat (events by type and day) |
| `services/hub_trace.py` | adapter from a figure id to `trace` results, so "Why this number?" has one entry point |
| `services/hub_ui.py` | the asset registry, page template, glossary, labels (one source for `HUB.LABELS` and `GLOSSARY`) |

- **Assets:** package folder `factory/hub_ui/`.
  - `kit.css`, `shell.js`, one script per page, `pages/*.html`, `fonts/` with licences.
  - Ported from the demo; the prototype test hooks are removed.
  - Shared JS pieces are factored into `shell.js`: works list, chips, tooltip, hash state, popovers, drawer, trace panel.
- **Routes** (thin):
  - `/p/<slug>/ui/<page>`
  - `/p/<slug>/ui/assets/<name>` (versioned, immutable)
  - `/p/<slug>/ui/data/<payload>.json`
  - `/p/<slug>/ui/trace?figure=<id>`
  - One write route only: "add to snowball" on Foundations. It goes through the existing allow-listed act and the auth seam, and records the researcher's act as an event. No other page writes.
  - The old hub stays at `/p/<slug>/` until cut-over.

## 7. Risks

- **Scope.** Eleven pages and nine services is a large plan.
  - Mitigation: phases with a review each (step 14), pages ported from a working demo, and analytics tested on toy fixtures first.
  - If time runs short, Living and Graph's River and Main path are the first to defer.
- **Graph size.** 7k nodes and 18k edges in the browser is feasible on canvas (WebGL is not needed). Mitigation:
  - The payload holds positions-free nodes with degree.
  - Edges are filtered by default to corpus and first-ring nodes.
  - The full set loads on demand.
- **JS quality.** The demo has about 5k lines by several agents.
  - Mitigation: factor shared pieces into `shell.js`, keep each page script under ~900 lines, add `// @ts-check` with JSDoc, and run `tsc --noEmit` only if node is present (non-gating).
- **Untested interactions.** Mitigation: the browser smoke in step 12 drives the main paths. The rest is covered by the live check.
- **Collision with IDEA-96.** None until step 13, which is done on a fresh rebase.
- **Data defects found by the views** (sets, citation sums, codebook): a fix belongs to the owning service, with its own test, and is noted in the handoff.
