# Plan: one roof — the factory's data and products under the factory folder

Date: 2026-11-11 · Status: decided by the researcher, not started (nothing moved; the copy script is written and untested beyond its precondition check) · Origin: pilot `agentic-science` · Backlog: IDEA-55

## Problem

The pilot's material is spread over `research-factory-pilot` (3.1 GB: the data root, 1,590 files of
scripts, specs and logs, the researcher's documents, staging PDFs, validation evidence, old product
copies) and the repository. The researcher cannot tell where things live; a new project would get none
of the pilot-only material. Some products (the backlog board, the portfolio) are about the factory,
not about one project, and have no home.

## Decisions (researcher, 2026-11-11)

1. Nothing factory-relevant stays in the pilot folder.
2. Two levels of hub: a **factory hub** (all projects, the backlog board, factory health, the miner
   registry across projects, skills) and a **project hub** per project (what `factory site build`
   makes today).
3. The data root is `data/` **inside the repository, git-ignored** (`/data/` is in `.gitignore`).
4. The move happens **after the v2 miner run ends**; nothing is moved while sessions, `factory-mcp.json`
   or the run scripts point at the current paths.

## Layout

```
research-factory/            code, specs, plugin, docs                      (git)
data/                        the factory's data root = FACTORY_ROOT         (git-ignored)
  hub/                       the factory hub
  projects/<slug>/
    events/ blobs/ library/  the data (as in the pilot's root/)
    docs/                    research plan, protocol, goal, questions, demo log
    inputs/  validation/     staging PDFs, validation evidence
    ops/                     run scripts, specs, logs (until `factory mine run`, IDEA-51)
    archive/                 old product copies, backfill
    site/                    the project hub
```

## Safe because

Events and blobs contain no absolute path (checked 2026-11-11: no occurrence of the pilot folder in
either), so the data root is relocatable by copying. `site/` holds machine paths (symlinks to files)
and is rebuilt (`site build --force`).

## Procedure (`scripts/migrate_pilot_to_data.sh`)

Copies, never moves or deletes; a dry run by default; refuses to run while a miner session, an
autopilot script or the hub server runs, or if `/data/` is not git-ignored. Steps: copy the data root;
copy the researcher's documents, inputs, validation, `screeners/` and old products into the project;
then by hand: `--verify` (checksums and event counts), `factory check` and `mine status` against the
copy, `site build --force`, repoint `FACTORY_ROOT`, `factory-mcp.json` and `hub.sh`; keep the pilot
read-only for a week before archiving it. `root-backup-2026-11-07` stays where it is.

## Follow-ups (not part of the move)

- The factory hub: a registry of the projects under `data/projects/`, one page listing them with
  status, the backlog board (now a product of the project hub) and factory health; slice 7a (portfolio,
  IDEA-01) is the base.
- `ops/screeners` shrinks as `factory mine run` (IDEA-51) and project objects (IDEA-50) replace the
  scripts and specs.
- `site` becomes `data/products/<slug>` only if the researcher wants products apart from the project;
  the layout above keeps them in the project.
