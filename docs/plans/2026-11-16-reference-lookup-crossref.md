# Plan: reference lookup without relying on OpenAlex (IDEA-89)

Status: merged (IDEA-89, backlog: built, reviewed, merged 2026-11-16; decision 130)

Date: 2026-11-16 · Branch: `reference-lookup-crossref` · Decision: 130 (proposed, this plan)

## Goal
Reference resolution (`services/reference_resolve.py`, `references re-resolve`) stops depending on
OpenAlex. Researcher's ruling (2026-11-16): the bulk re-resolve of 2026-11-15/16 used up the
OpenAlex key's daily quota after ~1,000 lookups (every request 429 from ~06:30); ~21,500 links
remain `source-error`; "do not rely on OpenAlex".

## Facts from the code (read before building)
- `reference_resolve.resolve_entries`: identifiers → corpus, then arXiv `id_list`, then OpenAlex
  `doi:` filter in chunks of `LOOKUP_CHUNK` (50); titled entries → corpus title match, then one
  OpenAlex `title.search` per entry with `limit=TITLE_SEARCH_LIMIT` (10).
- `sources/openalex.py` requests `per-page` = its page size (200) even when `spec.limit` is 10, then
  truncates ("truncated by caller-supplied limit", 223 runs last night): 20x the data per lookup.
- `sources/crossref.py` (`CrossrefSource`) serves only `QueryPurpose.STATUS` (retraction notices);
  it is not in `sources/registry.default_sources()`.
- `reference_items.flags_for(title)` already flags unusable titles (author-list, et-al,
  leading-noise, no-title, too-short). Junk titles such as "generated by l a t e xml" were still
  searched last night.
- Reference layers: `reference_layers` (agent assignments by `item_key`, scheme version) and
  `reference_layer_labels`; items come from `reference_items` (entries grouped into items,
  `CitedItem.key` and `aliases`). The scheme marks layers with `snowball`.

## Tasks (TDD for every task; tests offline with fake HTTP as the existing source tests do)

### T1 OpenAlex asks only for what it keeps
`OpenAlexSource`: when `spec.limit` is set, `per-page` = `min(page_size, spec.limit)`. Same
records returned; the truncation note stays only when more existed. Test: the request params of a
limited title search carry `per-page` 10.

### T2 Crossref as a works lookup source
Extend `sources/crossref.py` with a works lookup for `QueryPurpose.PROBE` (keep the STATUS path
unchanged): `QueryKind.FILTER` with text `doi:<a>|<b>|...` → Crossref `/works?filter=doi:a,doi:b`
(rows = number asked); text `title.search:<query>` → `/works?query.bibliographic=<query>&rows=<limit>`.
Parse each item into the same record type OpenAlex returns to resolution (title, authors with
family names, year from `issued`/`published`, DOI, container title, type), archiving every page
as the other sources do (`RawPage`, budget, polite pool `mailto`, redaction). Register it in
`default_sources()` as `crossref`. The query text format stays the one `reference_resolve`
already builds, so resolution can switch sources by name. Tests: parse fixtures (journal article,
preprint with `posted`, missing year), DOI list, title query rows, HTTP error → FAILED/PARTIAL,
429 handled by `PoliteClient` as elsewhere.

### T3 Resolution uses Crossref by default; OpenAlex is an explicit option
`resolve_entries` and `re_resolve` take `lookup_source: str = "crossref"` (one of `crossref`,
`openalex`; validated at the boundary). arXiv `id_list` first stays. DOIs and titles go to
`lookup_source`. The run records its source as today (provenance unchanged in shape). CLI
`references re-resolve --source crossref|openalex` and `references extract --source ...`;
MCP `references_extract` gains an optional `source` with the same default. A title lookup is
skipped when `flags_for(entry.title)` is non-empty: the entry settles as
`unresolved / no-identifier-no-title` (an unusable title is no title), no request made. Do not
bump `MATCHER_VERSION` (the matcher is unchanged). Tests: default source is crossref; flagged
title makes no request; openalex still selectable; unknown source refused writing nothing.

### T4 Re-resolve only what matters
`re_resolve(..., layers: Sequence[str] | None = None)`: when given, only entries whose cited item
(via `reference_items`, matching `key` or any alias) carries one of these layers under the latest
scheme version (agent assignment, a human label wins over it) are retried; others are left as
recorded and counted in the summary as `skipped-layer`. CLI `--layer <id>` (repeatable) and
`--snowball-layers` (the scheme's layers with `snowball: true`). Unknown layer id refused.
Summary lines print how many entries were selected, skipped by layer, skipped by flagged title.
Tests on a small fixture project with a recorded scheme and assignments.

### T5 Docs
Decision 130 in `docs/decisions.md` (Proposed): Crossref is the default reference lookup source,
OpenAlex optional; flagged titles are never searched; re-resolve can be restricted to layers.
Backlog IDEA-89 status "built, not reviewed" when landed. Regenerate `docs/MAP.md` after merge.
