## Goal
Turn the verified repository into things a researcher reads, writes and hands over, without letting any of them introduce an unverified statement. Four products:
1. **Views**: layered, read-only projections of the corpus and graph (onion rings around the focus, an evidence/benchmark coverage map, horizon time series and leaderboards over time), each a deterministic builder output that names its filter and the event log position it was computed at.
2. **Writing**: the platform assembles verified claims, quotes, cells and lineage edges into a structured outline; Claude writes prose sentence by sentence through MCP; every claim-bearing sentence names its supports; deterministic checks run at write time; an independent verifier session judges whether each sentence is supported by the spans it cites; unsupported text is flagged in every rendering and blocks release. The same verifier machinery checks the citations of an external manuscript against the cited sources (claim verification, line 11).
3. **Exports**: BibTeX, CSL-JSON, a PRISMA 2020 flow diagram (SVG), an RO-Crate of the project, and nanopublications of claims and stated edges, all derived, deterministic, and free of library text.
4. **Briefings** (IDEA-09): a project briefing for a human (reading path) and a versioned context pack for a new agent session, both builders over events.

Pilot for acceptance: **best linear attention mechanism for vision models** — a related-work section of about 15 sentences on linear attention for vision is outlined, written, verified and released in pilot mode, every claim sentence traceable through `trace` to a verified span; the BibTeX of its cited works, the PRISMA SVG and an RO-Crate are exported; the onion view and the leaderboard timeline of one comparability group are produced.

## User flow
1. **Views.** `factory view onion` shows rings of works around the included corpus with each work's processing depth; `factory view coverage` shows which methods have results in which comparability groups (counts only); `factory view horizon` shows activity per idea and year and the record timeline inside each comparability group. Over MCP the same views are `view_onion`, `view_coverage`, `view_horizon`, `view_timeline`.
2. **Outline.** `writing_outline` returns, for a declared scope (default: the included corpus), sections built from confirmed ideas in lineage order, comparability groups, unattached claims and a "what the corpus does not support" section. Every outline slot lists support ids only.
3. **Draft.** The researcher or Claude creates a draft (`draft_create`) pinned to an outline hash. Claude pulls a slot (`draft_next`), sees the supports with their verified quotes, and records sentences (`draft_write`), each with a class and its supports. Deterministic checks reject malformed sentences and flag risky ones.
4. **Verify.** A separate session pulls sentences (`draft_verify_next`) and sees only the sentence, its immediate predecessor as context, and the support spans; it records a verdict with the exact sentence part it judges and the support substring it relies on (`draft_verify_record`). The platform verifies both substrings.
5. **Audit and revise.** The researcher audits a sample of `supported` verdicts in the CLI; flagged sentences are revised (a new sentence supersedes the old) and re-verified.
6. **Render and release.** `factory draft render --review` shows every sentence with its status, supports and quotes; `--clean` renders prose with citations and a bibliography. Release (`factory draft release`) is a gate: it is refused while a claim-bearing sentence is unchecked, flagged or stale, under the policy of ruling 13.
7. **Manuscripts.** `factory manuscript add paper.tex --bib refs.bib` stores an external manuscript in the library, segments it, resolves its citations to corpus works; verifier sessions check each cited sentence against the cited source; `factory manuscript report` lists verdicts.
8. **Exports and briefings.** `factory export bibtex|csl|prisma|crate|nanopub` writes files to a path the researcher names; `factory briefing` prints the human briefing; `briefing_get` serves the agent context pack and records which pack the session received.

## Rulings

Every ruling is a recommendation awaiting confirmation. Options are listed; the recommended option is marked **[confirm]**.

### Views
1. **View contract.** (a) Each view is a builder in `services/` that returns a typed, JSON-serialisable read model with a common header `ViewMeta` (view name, view version, project, the active filter, `as_of` = id of the last projected event, `truncated`, notices); renderers (Markdown, CSV, DOT, SVG) are pure formatting; no view is stored as an event. (b) Views stored as blobs on each build. (c) An HTML user interface in the platform. **Recommended: (a) [confirm].** Rendering into pages is slice 7a's concern; if 7a adopts a different envelope, this slice adopts 7a's and keeps the content fields. `as_of` rather than the projection's `state_hash` because `Index.state_hash` reads every table and does not scale to 10^6 rows.
2. **Onion rings.** (a) Ring *k* is the set of works at undirected hop distance *k* from the focus over the selected edge types (default `cites`, `builds-on`, `improves-on` in G2-D's default status filter), focus = works with final outcome `INCLUDED` at the last declared stage; (b) rings by region membership (focus region, adjacent regions); (c) rings by processing depth. **Recommended: (a) [confirm]**, with processing depth as a second dimension of every ring and regions as an overlay (a node lists its regions once the regions slice exists; until then the overlay is empty and the view says so). The focus never contains seeds as seeds (decision 43): a seed's work appears only as the corpus work it is.
3. **Processing depth.** Computed per work, highest level reached: `indexed` (work record or G1 external work), `screened` (a final title/abstract or full-text outcome), `extracted` (a current evidence or contribution unit), `verified` (at least one final row with status `agreed` or `resolved`, or an audited row). Computed in SQL per ring, never typed. **[confirm]**
4. **Bounds.** `ONION_MAX_RING = 3` (default 2), `VIEW_MAX_NODES = 500` nodes listed per ring (counts are always complete, computed with SQL aggregates over a connection-local temporary table of visited ids); traversal is level by level with indexed reads (G2-D ruling 10); no view loads the graph. **[confirm]**
5. **Coverage map.** (a) Matrix of normalised `method_name` × comparability group with cell = counts (independent rows, copied rows, works), never values; (b) values in cells. **Recommended: (a) [confirm]** — decision 41 forbids ranking across groups, and a matrix of values invites it. Values appear only inside one group (the evidence report, the timeline). A second matrix, confirmed ideas × groups, uses contribution `result_row` links (slice-3b ruling 2) and is shown only when such links exist.
6. **Leaderboard over time.** Within one comparability group and value unit (evidence-report rulings 2, 5, 6): order independent rows by the date of their work; a row is a *record* when its value is strictly better than every earlier dated row (ties at equal date are all records); per year, the Pareto frontier of rows dated up to that year on each declared cost axis (reusing `evidence/pareto.py`). Date: (a) `Work.dates.published`, undated works counted and listed, never guessed; (b) the date of the document version the row was extracted from. **Recommended: (a) [confirm]**, with the limit stated that a result first reported in a later preprint version is dated by the work. No timeline crosses groups; a group with an unknown or conflicting direction has no timeline (as no frontier, evidence-report ruling 5).
7. **Horizon scanning.** The platform computes activity series only: included works per year per confirmed idea, new confirmed ideas per year (by origin date), new stated or confirmed lineage edges per year (by citing work date), record events per group per year. It never labels a topic "emerging" and computes no citation-velocity or bibliometric score (slice-3b out-of-scope list). A statement such as "kernel-based methods dominate since 2021" is a draft sentence with `stat` supports (ruling 10) or an interpretation (slice 3c). Every horizon view states the corpus horizon: the latest search or watch date per source, and that later work is absent. **[confirm]**

### Writing and verification
8. **Where drafts live (no literature text in git).** (a) Draft sentences are events in git (they are authored text, not literature); sentences reference supports by id and never copy quote text; quotes appear only in renderings, taken from the existing extraction events. External manuscripts (any text not written through the factory, including the researcher's own manuscript) are stored in the git-ignored library by hash; their events carry sentence ordinals, character offsets and hashes, never their text; agents read them through a read tool, as `document_read` serves conversions, so no `input_blob` contains manuscript text. Rendered drafts are written to stdout or to a path the researcher names, never into `projects/<slug>/`. (b) All drafts in the library, events carry hashes only (loses the provenance of authored text). (c) Drafts as freely edited Markdown in a tracked directory, verified on demand (breaks events-as-truth and per-sentence provenance). **Recommended: (a) [confirm].**
9. **Sentence classes.** The writer declares one class per sentence; the platform checks the lexical constraints.
   - `claim`: states something about the literature. At least one support; the full deterministic checks of ruling 11; independent verification required.
   - `synthesis`: states an aggregate (counts, consensus, comparison within a group). At least one `stat` or group support; the same checks; verification required.
   - `interpretive`: the writer's reading or explanation. May cite reviewed interpretation-layer items (slice 3c) and evidence supports; always rendered with the label *interpretation*; never counted as verified; may not contain numbers.
   - `structural`: headings, transitions, scope statements. No supports; refused if it contains a number token, a citation pattern, a work's first-author surname with a year, or the name of a method that is a support anywhere in the draft.
   **[confirm]**
10. **Supports.** A support is a typed reference: `claim` (`clm_…`, live, pass A, work `INCLUDED`), `cell` (`rk_…/<field>`, a final row of a current unit), `item` (a live, final contribution row, slice 3b), `edge` (`rel_…` or `cit:…`, `stated` or `confirmed`), `group` (`grp_…`, an evidence group), `stat` (a computed figure from a closed registry, e.g. `stat:group-works:grp_…`, `stat:idea-members:ida_…`, `stat:prisma:included_in_review`, `stat:records:grp_…:<year>`; its value is computed and stored on the sentence at write time), `interp` (`int_…` or `cpt_…`, reviewed, only for `interpretive` sentences). Unreviewed or `wrong` interpretation items, inferred edges, stale rows, unconfirmed ideas, excluded works and screening seeds are never supports. Sentences are bounded (`SENTENCE_MAX_CHARS = 400`; at most 6 supports). **[confirm]**
11. **Deterministic checks at write time** (platform; refusals write nothing, flags are stored on the sentence):
    - *Refused:* unknown or ineligible support; class constraint violated; **number-unsupported** — a number token in the sentence (`extraction/numbers.py::numbers_in`) that equals no number in a support's quote, no canonical value of a cited cell, no stored `stat` value, and no publication year of a support's work; more than one sentence (terminal punctuation followed by a capital letter outside abbreviations).
    - *Flagged (to the verifier and in renderings):* **citation-mismatch** — a citation pattern in the text (the `CITATION_PATTERNS` of the ml-benchmark pack) whose surname matches no support work's first author (`references/match.py::surname_key`); **quantifier-without-statistic** — a word of the closed list `QUANTIFIERS` (all, every, none, always, never, consistently, most, majority, best, state-of-the-art, outperforms all) in a `claim` sentence without a `stat` or `group` support; **cross-group** — a comparative or superlative in a sentence whose cell supports span more than one comparability group (decision 41); **single-source-generalisation** — a `synthesis` sentence whose supports come from one work.
    Citations are not typed by the writer: the renderer appends citation keys of the support works in support order, so a sentence cannot cite a work it does not use. **[confirm]**
12. **Independent verification (the semantic check).** (a) One verifier pass per `claim` and `synthesis` sentence, in a session that has written no sentence of the draft, model different from the writer's where available (enforced in `systematic`, recorded in `pilot`, as decision 37), seeing only the sentence, the preceding sentence marked as context, and the support spans (quotes, cell values with quotes, edge basis quotes, stat values); never the writer's `input_blob` or reasoning (R-51). Verdicts: `supported`, `partial`, `unsupported`, `contradicted`, `overstated` (the sentence is stronger than the spans: hedging, scope, quantifier). Every verdict other than `supported` names the offending sentence substring; every verdict names, per support used, a substring of that support's span; the platform checks both substrings verbatim. A human audit draws a sample of `supported` verdicts: n = min(N, max(ceil(0.1·N), 20)) per draft, error ceiling `DRAFT_VERIFY_ERROR_CEILING = 0.05` (advisory in `pilot`, a gate in `systematic`). (b) Dual verification of every sentence with agreement. (c) Human verification only. **Recommended: (a) [confirm]**; dual verification is a later option if the audit error exceeds the ceiling.
13. **Sentence status and the release gate.** Status is computed on read, never stored: `structural`, `interpretive`, `unchecked` (no verdict yet), `supported` (latest verdict `supported`, audit not `incorrect`), `flagged` (latest verdict not `supported`, or audited `incorrect`), `stale` (a support became stale, superseded, excluded or rejected, or a `stat` value changed). Release gate policy by rigor mode until slice M declares gate policies: `exploratory` — agent may release; flagged, unchecked and stale sentences are rendered with visible markers and counted on the title page; `pilot` — release by agent or human after the audit is drawn and labelled; no `stale`; flagged and unchecked sentences rendered with markers and listed in an appendix; `systematic` — release by the reviewer of record only (R-39), with zero `flagged`, `unchecked` or `stale` claim-bearing sentences and the audit under the ceiling. A released draft records the `as_of` position, counts by status and the policy it was released under. **[confirm]**
14. **How unsupported text is flagged.** In `--review` renderings each sentence carries its status tag and its supports with quotes. In `--clean` renderings a sentence that is not `supported` (or `structural`/`interpretive`) is wrapped in `[[UNSUPPORTED: <status>; <reason>]] … [[/]]`, interpretive sentences in `[[INTERPRETATION]] … [[/]]`; markers are plain text so they survive copy-paste into a word processor and are found by search; a clean rendering with no markers is possible only for a draft in which every claim-bearing sentence is `supported`. The bibliography lists only works cited by `supported`, `interpretive` or marked sentences, and the methods appendix states the counts. **[confirm]**
15. **Outline.** A deterministic builder `writing_outline(project, scope)`. Sections: (i) one per confirmed idea, in lineage order (topological over stated and confirmed `builds-on`/`improves-on` idea edges, ties by origin date then id), listing the origin, members, their `base-idea`, `addition` and `limitation` items, and stated edges; (ii) one per comparability group with at least two works, listing group id, frontier cells and `method_conflicts` (R-42: disagreement is a mandatory slot, not averaged); (iii) live claims of included works not attached to (i) or (ii), by claim type; (iv) "not supported by the corpus": evidence-report limits and G2-D `no_stated_base` categories. The outline holds ids only; its id is `OL@<sha8>` over its canonical JSON. A draft pins one outline; a new outline is a new pin and marks sentences whose supports left the outline `off-outline` (advisory). **[confirm]**
16. **Human authorship.** A human may write sentences in the CLI (`author = human`); they pass the same checks and the same verifier (an agent may verify a human's sentence; a human verifier may verify an agent's). The writer of a sentence never verifies it, whoever writes. **[confirm]**
17. **Claim verification of external manuscripts.** Formats: Markdown or LaTeX with a `.bib` or CSL-JSON file, or a reference-list section; PDF once decision 49 names a converter. Segmentation by a pinned, rule-based splitter (`writing/segment.py`, version recorded); citations parsed (`\cite…{}`, `[@key]`, numeric markers via G1 `references/markers.py`) and resolved to corpus works through G1's matcher (identifier and title-exact resolve; fuzzy matches need a human confirmation as G1 ruling 3). Each cited sentence is a unit; the verifier reads the cited work's pinned conversion (`document_read`) and records a verdict with an anchor and a verbatim quote from the cited source (checked as R-32 quotes), or `cannot-verify` with reason `source-not-in-corpus`, `no-full-text` or `citation-unresolved`. Uncited sentences are not judged by the platform; the verifier may flag `uncited-claim`, recorded as advisory. Audit as ruling 12. **[confirm]**

### Exports
18. **Bibliography keys and formats.** BibTeX (UTF-8; `--ascii` escapes) and CSL-JSON, from `Work` records only. Key = the work id without the `rf:` prefix and the hash suffix (`katharopoulos2020-transformers-are-rnns`), with the hash suffix restored on collision; stable because work ids never change. Scopes: `included` (default), `corpus`, `draft:<drf_…>` (works cited by the draft's rendered sentences), explicit ids. Entry types mapped from `WorkType` (preprints as `@misc` with `eprint`/`archivePrefix`). Fields absent from the work are omitted, never filled. **[confirm]**
19. **PRISMA diagram.** (a) A deterministic SVG from a fixed PRISMA 2020 template (databases and other-methods columns; identification, screening, retrieval, eligibility, included boxes) filled from `prisma_flow` and `full_text_boxes`; a `provisional` banner while works are pending; no layout engine, no font measuring beyond a fixed character-width table. (b) Graphviz DOT. (c) Mermaid. **Recommended: (a) [confirm]**, with (b) as a secondary format if the researcher wants editable output.
20. **RO-Crate.** RO-Crate 1.1, a directory (or zip) containing `ro-crate-metadata.json`, the event log, text blobs, the protocol, rendered reports (PRISMA Markdown and SVG, methods, evidence report Markdown and CSV, search report, lineage JSON, released drafts in clean form), the bibliography, and a `library-manifest.json` listing each library document by hash, route, URL, licence and retrieval date — **never library content** (R-47; decision 39), even for openly licensed documents. Each report is a `CreateAction` whose instrument is the factory version and whose object is the log position; agents appear as `SoftwareApplication` entities per (model, skill reference) with event counts. Dates come from the last event, so a crate is byte-identical for the same log. **[confirm]**
21. **Nanopublications (resolves Open decision 22).** (a) The platform's own schema stays the source of truth; nanopublications are a one-way export: one nanopublication per live claim of an included work and, with `--edges`, per stated or confirmed lineage edge. Assertion: the claim (statement, claim type) linked to the work's DOI or arXiv IRI with `cito:citesAsEvidence`; provenance: `prov:wasDerivedFrom` the work, the anchor, the conversion hash, `sha256` of the quote, `prov:wasAttributedTo` the agent (model, skill reference) and the extraction event; publication info: the researcher (ORCID when configured), the export date (last event). Base IRI `http://purl.org/nanopub/temp/` (the placeholder that nanopub tools replace when signing); TriG written by the platform with sorted triples; no signing, no trusty URIs, no network publishing (the researcher signs and publishes with nanopub tooling). Quote text excluded by default, included with `--with-quotes` (local use). The agent's `strength` is exported as the agent's judgement, never as evidence strength. (b) Adopt nanopublications as the internal claim format. **Recommended: (a) [confirm].**
22. **No literature in exports, determinism.** Every export is derived from events and blobs, never reads the library except the manifest's metadata, is byte-identical for the same log, and names its scope and log position. Over MCP only bibliography exports (capped at `MCP_EXPORT_MAX_WORKS = 2000`) and `draft_render` are offered; crate, PRISMA SVG and nanopub exports are CLI only (they write files). **[confirm]**

### Briefings (IDEA-09)
23. **Content.** A briefing is a builder output: question (elements, non-goals), current protocol id and amendments with reasons, rigor mode, gates passed (PRESS, calibration, agreement, audits) with dates, corpus counts (PRISMA), confirmed ideas in lineage order with origin works (the reading path: origin first, then improvements along `path`), comparability groups with work counts, open issues (`check` findings), pending human decisions, released drafts. Human form: Markdown. Agent form: JSON context pack, bounded at `BRIEFING_MAX_CHARS = 40000` with truncation stated. **[confirm]**
24. **Agent context pack is recorded.** (a) `briefing_get` stores the pack as a blob and records `briefing.served` (system actor) with the session id, blob hash and `as_of`; the agent view applies the existing agent filters (`check.agent_view`, `agent_evidence`, `agent_methods`, `agent_trace`): no held-out recall, label-derived rates or seed identities. Sessions that have joined a pass are refused (decisions 43, 48). Later agent events of that session can then be traced to what the agent was told. (b) A new `context` field in the event envelope (changes 00-system §4.2). **Recommended: (a) [confirm].**

### Cross-cutting
25. **Pass sessions.** Every tool of this slice is refused to a session that has joined any screening, extraction or contribution pass (decisions 37, 43, 48); a session that has written sentences of a draft cannot verify that draft; a verifier session cannot write sentences of the draft it verifies. **[confirm]**
26. **Scale.** No view, outline or export loads the corpus or the graph: counts by SQL aggregates, traversals by indexed level-wise reads, exports streamed in deterministic order. The evidence report's `final_rows` and `grouped_rows` load all rows today; plan V-B adds per-group accessors (`group_index`, `rows_of_group`) used by views and the outline, and leaves the report unchanged. Scale tests (marked `slow`) use 10^5 works and 10^6 edges. **[confirm]**

## Design

### Builders and renderers
```
events -> projection (index) -> builders (services/)          -> renderers (pure)          -> outputs
                                 views.py   onion.py depth.py  views/render.py               stdout, --out path,
                                 coverage.py horizon.py        views/timeline.py             MCP text (capped)
                                 outline.py drafts.py          writing/render.py
                                 briefing.py exports.py        exports/{bibtex,csl,prisma_svg,crate,nanopub}.py
```
Builders read the projection only (the library is read only by `manuscript_read` and `document_read`, both existing patterns); renderers take a read model and return text. No builder writes an event except the tools of the writing module and `briefing_get`.

### Writing module (authoring + quality regime + gate)
| Platform (deterministic, offline) | Agent (Claude via MCP) |
| --- | --- |
| Build the outline; serve slots with supports and quotes; check classes, supports, numbers, citations, quantifiers, groups; store `stat` values | Write sentences for a slot with class and supports |
| Serve verification units with spans only; verify verdict substrings; compute status and staleness; draw the audit sample | Judge whether a sentence is supported by its spans; name the unsupported part |
| Render review and clean forms with markers; enforce the release gate; derive every count | Never sets a status, count, citation key or identifier |

Staleness is computed on read: a sentence is `stale` when any support is no longer eligible (claim superseded, row stale or no longer final, work no longer included, edge stale or rejected, interpretation `wrong` or superseded) or a `stat` recomputes to a different value. A stale sentence keeps its verdict history; revising it (a new sentence that supersedes it) restarts verification.

### Manuscript verification
`manuscript.added` records the library hash, format, the companion bibliography hash and the segmenter version; `manuscript.segmented` records per sentence: ordinal, character offsets, `sha256` of the text, citation keys found; `manuscript.citation_resolved` records the key-to-work resolution with G1's method and score (fuzzy ones wait for `manuscript.citation_decided` by a human). Units are (manuscript, sentence ordinal, cited work). The verifier sees the sentence through `manuscript_read` (text from the library, never stored in an event) and the cited work through `document_read`; its verdict carries anchor and quote from the cited work's pinned conversion, checked with `quote_in_element`. The report joins verdicts with sentence text read from the library at render time.

## Acceptance criteria
1. **View determinism.** Each view built twice from the same log is byte-identical in JSON; `as_of` equals the last projected event; the filter is stated.
2. **Onion.** On a constructed graph, rings, counts by processing depth and truncation match the expected values; a seed's work appears only as a corpus work; inferred edges do not affect rings unless requested.
3. **Coverage and timeline.** The coverage matrix carries counts only; a timeline never mixes groups or units; undated works are counted; a group with an unknown direction has no timeline.
4. **Horizon.** Activity series equal hand-computed counts; the corpus horizon (last search date per source) is printed; no output contains an "emerging" label or a citation score.
5. **Outline.** Built twice, identical `OL@` id; idea sections in lineage order; method conflicts and limits appear as slots; ids only, no quote text in the outline blob.
6. **Write-time checks.** Each refusal (ineligible support, class violation, unsupported number, two sentences) and each flag (citation mismatch, quantifier, cross-group, single source) fires in a constructed case; nothing is written on refusal; valid sentences of the same batch are written.
7. **Independence.** A writer session cannot verify its draft; a verifier session cannot write in it; in `systematic` a verifier with the writer's model is refused.
8. **Verdict spans.** A verdict whose sentence substring or support substring is not verbatim is refused.
9. **Status and staleness.** Superseding a claim, excluding a work, rejecting an edge or changing a `stat` value turns dependent sentences `stale`; revising restarts verification.
10. **Rendering and markers.** A clean rendering of a draft with a flagged sentence contains its marker; a draft with all claim sentences `supported` renders without markers; interpretive sentences are labelled; the bibliography lists only cited works.
11. **Release gate.** Release is refused per ruling 13 in each mode; `draft.released` records counts and policy.
12. **Manuscripts.** No manuscript text in any event, blob or error; a sentence citing an unresolved key yields `cannot-verify: citation-unresolved`; a verdict quote not in the cited conversion is refused.
13. **Exports.** BibTeX and CSL-JSON round-trip through a parser in tests; keys are stable across rebuilds; the PRISMA SVG numbers equal `prisma_flow`; the RO-Crate contains no library file and lists every library document in the manifest; nanopublications parse as TriG with four graphs each and contain no quote text by default; every export is byte-identical across rebuilds.
14. **Briefings.** The agent pack withholds what the agent views withhold; `briefing.served` links the session to the pack; a pass session is refused.
15. **Trace.** `trace` from a sentence reaches the question through each support kind; `trace --forward` from a claim lists its sentences.
16. **Check.** Each finding appears in a constructed case; none carries document or manuscript text.
17. **Scale.** On a synthetic index of 10^5 works and 10^6 edges, `view_onion` (ring 2), `view_coverage` and a bibliography export of 10^5 works finish within 5 s each without loading all rows (`slow`).
18. **Pilot.** The pilot related-work section is released in pilot mode; counts by status, the audit error rate, the number of refused and flagged sentences are reported; BibTeX, PRISMA SVG and RO-Crate are exported; the onion and one timeline are produced.
19. **Quality.** `mypy --strict`, ruff; coverage ≥ 90% for `services/` and `model/`; TDD; the write-time checks, verification independence and release gate by subagent-driven development.

## Open questions
1. **Section-level claims.** Should a sentence be allowed to rely on the preceding sentence's supports ("This approach …")? Recommendation: no; each claim sentence names its own supports; the verifier sees the preceding sentence only as context.
2. **Verifier cost.** One verifier call per claim sentence; a 15-sentence section is cheap, a 200-sentence review is not. Recommendation: accept for drafts; for manuscripts, verify cited sentences only.
3. **Stat registry growth.** New `stat` kinds need code. Recommendation: a closed registry in `writing/stats.py`, extended per plan; agent-defined statistics are not supports.
4. **Regions in the onion.** If the regions slice defines region membership by labels rather than graph structure, rings and regions stay separate dimensions. Recommendation: keep rings structural (ruling 2) whatever regions become.
5. **Claim strength in prose.** Claims carry the agent's `strength`; should `overstated` verdicts compare hedging against it? Recommendation: no; the verifier compares the sentence with the spans, not with the extractor's judgement.
