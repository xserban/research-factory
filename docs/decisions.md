| 37 | Screening independence and audit | Decided (2026-11-04; confirmed by the researcher as implemented) | 1) Session identity: separate sessions, enforced. A session that has joined pass A cannot claim, record or read pass-B work, and vice versa; `screen_agreement` refuses when the passes share any session or any model. No per-agent claim token; subagents of one session cannot serve both passes. 2) Framing and order are fixed by the pass: A uses inclusion framing with criteria in protocol order; B uses exclusion framing with the same list reversed. Per-pass configuration is (framing, criterion order, seed, sessions, models); a shared session or model refuses. 3) Audit minimum: n = min(N, max(ceil(audit_fraction · N), audit_minimum)) over N agreed, dual-coded decisions; strata round(0.75 n) exclusions, rest inclusions, short stratum filled from the other. `pilot` and `systematic` reject audit_fraction < 0.02 or audit_minimum < 50; `exploratory` may declare less. 4) Audit error ceiling is a platform constant (AUDIT_ERROR_CEILING = 0.05 false-exclusion rate), advisory in `pilot`, a gate in `systematic`; not a protocol field, so existing P@ hashes are unchanged. 5) Calibration: sensitivity ≥ 0.9 in `pilot`, ≥ 0.95 in `systematic`, none in `exploratory`. Specificity is reported, never gated (R-31). Calibration is per pass and protocol version; an amendment requires recalibration. 6) Human acts (calibration labels, disagreement resolution, audit labels) enter via the CLI, or over MCP as relayed answers with the configured human as actor and `channel = mcp`; the calling session cannot join a pass, and a pass session cannot use these tools. 7) Visibility: while either pass has open tasks, `screen_agreement` refuses; afterwards it returns κ and the disagreement list with both verdicts. 8) Agreement unit: `promote` (include, cannot-assess) or `exclude`. `unsure` in either pass, or differing outcomes, is a disagreement routed to the human; two exclusions citing different criteria agree on outcome and lower only per-criterion κ. 9) Held-out seeds are screened like any record: tools withhold seed IDs and identifiers, not the works' rf: IDs, titles or abstracts; no task marks a work as a seed. 10) Partial dual coding (pilot): pass B's tasks are a recorded random sample of ceil(dual_sample · corpus size); other works stand on pass A alone and are listed as single-pass (promotion gap for plan 5). 11) Criteria order, concretely: criteria in protocol order are the inclusions then the exclusions, each by priority; pass A serves them in that order, pass B reversed.  12) Audit size, pilot example: with the defaults (audit_fraction 0.02, audit_minimum 50) the minimum binds for up to 2,500 agreed decisions; for a corpus of at most 300 records the audit is 50 works, or all of them when fewer than 50 are agreed.  13) `unsure` counts as not-promote in κ (`Verdict.promotes` is false for it), while it is still routed to the human as a disagreement (8).  14) A pass that fails the calibration gate needs a protocol amendment by the researcher (an amendment requires recalibration, 5); the screener does not retry, and the gate reasons it sees carry counts only, never a rate, a threshold or a label.  15) Reading results from a pass session: over MCP `screen_agreement`, `audit_sample` and the no-argument `calibration_label` are refused to a session that has joined a pass.
