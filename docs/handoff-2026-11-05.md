## How the work is run

One agent per whole plan, in its own worktree and branch, based on the current head. Then one opus review of the whole diff, a fix round by the same agent, a scoped opus re-review, a rebase onto the head, and a fast-forward of `plan-2d-extraction`. Run a full suite at milestones in a separate worktree: `uv run pytest -m "not network" -n 3 -q`. It takes 30 to 60 minutes under load.

This review loop found a Critical or several Important defects in nearly every plan. Do not skip it, and do not trust an implementer's report or a passing test as proof.

Put these in every brief:

- TDD, one commit per task, failing test first.
- Every agent-surface guard needs a test that fails when the guard is removed, proved by removing it. Ask reviewers to mutate guards in a throwaway copy.
- Projector handlers must be total, and a hand-written event that fails a guard must change nothing, on rebuild too. A logged event can never be removed. See `tests/test_forged_events.py` and `tests/test_experiments_forged.py`.
- Views must work and be empty with a notice on a fresh project. Test through real events.
- Scale tests must reach the real path on a realistic corpus. A patched or empty fixture proves nothing.
- A view composing sources must call each source's agent variant. Withholding belongs to agent paths only; the researcher's output stays complete.
- Resolve merges by hand, never by automatic union: check every `@server.tool()`, function tails, the tool-list pin, `OMITTED_WHEN_EMPTY`, the module list and `presets.py`.
- No `pkill`. No push or merge by agents. Agents report once.

## Held-out rule

Read the memory file `held-out-works-read-as-corpus.md`. Once a pass is open a held-out seed's work reads as any corpus work. Before a pass, agent tools must not name it, through role-blind guards. Withhold only seed records, seed ids, stated identifiers, held-out recall and rates, and an import's held-out part. Never filter or mask a work. A marker showing a work is held-out is itself an oracle. Judge a leak finding from the binding text, not from a reviewer's paraphrase. Over-hiding has been the more frequent mistake here, and withholding must not spread into the researcher's own reports.

## Practical notes

- Disk: this build filled a 228 GB disk once and spoiled a full suite. Each worktree `.venv` is about 180 MB and pytest temp directories reach several GB. Remove finished worktrees, and delete pytest temps only when older than the oldest running test.
- Load: more than about three concurrent test runs makes scale tests fail on timing and stretches a full suite to an hour. Scale-test timing failures under load (`test_scale_bounded`, `test_onion_scale`) passed when re-run alone.
- Usage: the 5-hour limit stops every agent at once; resume each by `SendMessage` after the reset.
- An agent with idle background work may resend its report in a loop. Stop it once its work is committed. For later work, a fresh agent can be cheaper than reviving a very long context.
